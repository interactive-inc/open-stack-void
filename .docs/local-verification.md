# ローカル検証

2026-10-25、パスキーを扱うブラウザの実動作、ローカル D1 と Durable Objects、公式 MCP SDK の接続、CLI、EmDash の編集・公開を検証した。初回登録の同時実行では所有者が一人だけ成立すること、承認を別の接続へ流用できないことも確認した。

検証用のブラウザ認証器とデータは通常の開発領域から分離した。アプリの初回登録をテストが奪わないことを優先するため。公開サイトも独立したテスト領域で編集し、元の内容へ戻している。

実ユーザーのクリップボードと実メールの配信、本番ドメイン、実環境への公開は検証していない。CLI の認証契約はテスト用クリップボードを注入して確認し、秘密値の実読み取りを作業中に行わない方針とした。[[client-access]]、[[resource-naming]]。

公開サイトの後続確認で概要リンクの 404 を検出した。CMS の本文を取り込む前のメニューだけを確認済みとしてしまったことが見逃しの理由だった。ローカル専用の非破壊 seed を追加し、通常環境へページ2件・記事3件を投入した。[[sample-content]]。

分離環境では seed の初回作成と再実行、編集保持、非公開の維持を検証した。記事の作成・下書き・公開・更新・非公開を実際の公開画面で確認し、管理画面の編集は自動保存された下書きと公開確認後の表示を分けて検証した。ヘッダー、フッター、本文、記事、分類、アプリへの99件のリンクをクリックし、到達した公開サイト10ページでは直アクセスと再読込も確認した。存在しないページと記事は引き続き404となる。

GitHub の接続ツールで interactive-inc/open-stack-void が公開リポジトリとして存在することを確認した。ローカルに LICENSE ファイルがないため、特定のライセンスは表明しない。

npm 移行後のリンク巡回では、サンプルアプリへの CTA が404となった。これは通常アプリをインストール検証のため停止していたことが原因で、非公開記事への古いリンクではなかった。CMS 検証にもアプリの独立したデータ領域を用意し、99件の200応答を要求したまま再度完走した。seed は vp run の入口から実行し、編集した概要が再実行後も維持されることを確認した。[[package-management]]。
