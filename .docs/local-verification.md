2026-10-26、会話の使い勝手と利用案内を追加した。単体試験18件に加え、二人の投稿、本人による編集・削除、他人からの変更拒否、古い版の上書き拒否、削除した本文の再送による復活防止、下書き保持を確認した。直近100件から外れた投稿も検索と履歴の読み込みで取得できる。端末の本人確認、招待、外部接続の承認・失効・取り消し、初回所有者の同時登録を含む操作試験6件が通過した。

説明の初期内容は使い方9ページを含む14件。分離した環境で初回投入と再投入、既存の編集・公開状態の保持、下書きと公開の切り替えを確認し、公開画面19ページ・213リンクを巡回した。携帯幅でも横にはみ出さず、会話の投稿欄と使い方への経路を確認した。実アカウントや本番データには変更を加えておらず、今回の変更は未公開。[[user-guide]]、[[chat-usability]]。

検証用の起動処理では、閲覧用の処理が裏で起動して試験の管理から離れないようにした。説明サイトの試験は独立したループバック接続を使い、名前解決や管理者権限を要する常駐設定は変更しない。

2026-10-25、パスキーを扱うブラウザの実動作、ローカル D1 と Durable Objects、公式 MCP SDK の接続、CLI、EmDash の編集・公開を検証した。初回登録の同時実行では所有者が一人だけ成立すること、承認を別の接続へ流用できないことも確認した。

検証用のブラウザ認証器とデータは通常の開発領域から分離した。アプリの初回登録をテストが奪わないことを優先するため。公開サイトも独立したテスト領域で編集し、元の内容へ戻している。

実ユーザーのクリップボードと実メールの配信、本番ドメイン、実環境への公開は検証していない。CLI の認証契約はテスト用クリップボードを注入して確認し、秘密値の実読み取りを作業中に行わない方針とした。[[client-access]]、[[resource-naming]]。

公開サイトの後続確認で概要リンクの 404 を検出した。CMS の本文を取り込む前のメニューだけを確認済みとしてしまったことが見逃しの理由だった。ローカル専用の非破壊 seed を追加し、通常環境へページ2件・記事3件を投入した。[[sample-content]]。

分離環境では seed の初回作成と再実行、編集保持、非公開の維持を検証した。記事の作成・下書き・公開・更新・非公開を実際の公開画面で確認し、管理画面の編集は自動保存された下書きと公開確認後の表示を分けて検証した。ヘッダー、フッター、本文、記事、分類、アプリへの99件のリンクをクリックし、到達した公開サイト10ページでは直アクセスと再読込も確認した。存在しないページと記事は引き続き404となる。

GitHub の接続ツールで interactive-inc/open-stack-void が公開リポジトリとして存在することを確認した。ローカルに LICENSE ファイルがないため、特定のライセンスは表明しない。

npm 移行後のリンク巡回では、サンプルアプリへの CTA が404となった。これは通常アプリをインストール検証のため停止していたことが原因で、非公開記事への古いリンクではなかった。CMS 検証にもアプリの独立したデータ領域を用意し、99件の200応答を要求したまま再度完走した。seed は vp run の入口から実行し、編集した概要が再実行後も維持されることを確認した。[[package-management]]。

## 最新版との統合

先の [[chat-usability]] と [[user-guide]] の成功記録は退避前の版に対するもの。504bdaeへの統合後の結果は別に取得する。検索と再接続は上流の処理を採用し、旧い検索API・画面を廃棄した。Astro開発サーバーを試験プロセスが直接管理するためignore-lockを維持し、CMS試験はシステムのプロキシ設定に依存しない分離ポートを使う。公開設定の復元はローカル変更であり本番作業ではない。

2026-10-27、統合後の `vp run verify` が成功。整形・lint・構造と文書・型・全ワークスペースのビルド、アプリ48件・CLI6件・初期設定保護3件の単体試験、基盤12件と依存ポリシー6件を確認した。アプリのブラウザ試験21件が成功し、追加の本文変更試験で本人と他人、未認証、同時編集、アーカイブ、削除後の検索と再送、利用停止後の変更拒否を検証した。サイトのブラウザ試験1件も成功し、14件の初期内容の再投入・編集と公開状態保持・記事の公開操作、19ページ213リンクの200応答を確認した。ブラウザの本人確認は仮想認証器によるもので実端末の検証ではない。

名前付きローカルURLの専用試験は不合格。既存のPortless応答はHTTPからHTTPSへ302を返し、指定したHTTPオリジンからは404に達する。分離したアプリの直接接続では初期状態を200で取得できたため、これをアプリ本体の検証成功と混同しない。既存プロキシの再起動、証明書・hosts・サービス変更は行わない。試験用アプリのプロセスだけを停止した。CMSとアプリの同時起動は生成設定を共有するため試験を順番に実行した。統合後の本番反映・実メール・実端末・通常の名前付きオリジンでの利用は未確認。[[local-origins]]。
