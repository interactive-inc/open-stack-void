# ローカルオリジン

ポート番号から開発先を判断しなくて済むよう、Portless で公開サイトとアプリに固定名を割り当てる。Windows の標準 DNS と Chrome では `.localhost` の解決が異なるため、Node クライアントでは指定したアプリの HTTP 接続だけをループバックへ向ける。Host と認証の Origin 検証は保持する。

OS の証明書信頼、hosts、ファイアウォールを変更しないため、ローカルでは HTTP を選んだ。Chrome が安全なコンテキストとして扱うことと仮想パスキーを実測した。外部共有や本番通信にこの選択を適用しない。

Portless 0.15.11 の Windows ワークスペース起動は 旧パッケージ管理の cmd ラッパーを起動できなかった。公式設定の名前とポートを読み、明示的な名前で各プロセスを起動する。Vite への包括的なホスト追加は取り除き、各サーバーの許可名と CORS は正確なローカル名へ限定する。

パスキーは RP ID に紐づくため、旧 localhost の資格情報は新しいアプリ名で使えない。認証データの削除による再初期化は行わない。既存利用者の移行手順は別途必要となる。[[local-verification]]、[[product-decisions]]。
