# 開発環境の目的

非開発者が複製して使い始められる、動作するフルスタックのひな形を作る。サンプルにチャットを選んだのは、認証、招待、権限、永続化、リアルタイム通信を一つの利用目的で確認できるため。

公開コンテンツの更新は開発から切り離す。[[content-ownership]] と [[chat-security]]。

操作手段を変えても権限が変わらないことを優先する。[[client-access]]。

その後のユーザー依頼で、Void Chat自体を業務で使える最小構成まで仕上げることを優先した。基盤と認証・認可を維持しながら、未読・返信・再送を追加し、公開サイトの主題を実際のチャット利用へ移す。ひな形としての拡張手段は副次的な案内に残す。判断の範囲と未決定事項は [[workday-chat]]。
