# Design

## Direction

Conversation is the primary surface. Keep labels short, reserve most screen space for messages, and put occasional management tasks behind dialogs. Do not add decorative dashboards, marketing filler, or explanatory cards.

## Components and tokens

Use shadcn/ui `base-maia` generated by the official CLI. Use the supplied neutral semantic color variables, Figtree font, radii, spacing, states, and focus treatment. Do not create parallel primitive components or hand-edit generated components. Public-site typography may use semantic HTML and the same tokens.

## Layout

Desktop: compact channel navigation beside a full-height conversation. Mobile: channel selector in the header and conversation below it. The composer remains visible; the message history scrolls independently. Management dialogs must fit the viewport and scroll internally.

## States

Show pending state on the affected action, keep failed message drafts, prevent duplicate submissions, and show one actionable error near its operation. Never replace missing data with fabricated success. Destructive member changes require confirmation. Secrets are masked on entry, never included in error text, URLs, or explanatory examples.

## Accessibility

Retain visible focus, keyboard navigation, accessible names for icon buttons, dialog titles, labels for inputs, semantic headings, and polite live updates for messages. Do not convey status by color alone. Test mobile overflow and dialog focus recovery.

## Public content

The EmDash homepage is compact and editorial: a CMS-controlled headline, a short paragraph, the chat entry point, and recent updates. CMS administration remains the upstream interface rather than a replacement editor.
