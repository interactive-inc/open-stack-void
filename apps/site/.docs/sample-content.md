# サンプルコンテンツの扱い

Open Stack Void がボイラープレート、Void Chat が同梱サンプルであることを紹介の主軸とする。独立したチャット製品や架空の会社として紹介しない。導入、認証、CLI／MCP、構成と拡張を題材に、EmDash のページと記事を編集できる例にする。[[content-ownership]]。

初期スターターはメニューを自動投入する一方、本文の投入はセットアップ時の選択まで待つ。この差によって未セットアップ環境の「概要」が 404 になった。前の検証はトップの編集反映と管理画面の到達だけを確認し、メニューを辿らなかったため見逃した。

ローカル seed は EmDash の公開 applySeed API を使い、内容と分類だけを追加する。全 seed を再適用すると既存メニューやウィジェットが再構成されるため対象から外す。既存 slug は下書き、非公開、ゴミ箱を含め保持し、ユーザーや認証情報は作らない。旧スターターからの名称移行は、CMS ユーザーが存在せず、名称と説明が両方とも旧既定値と一致する場合に限る。

seed を Web 公開後に呼べる仕組みにしない。開発時だけルートを組み込み、127.0.0.1 の正確な Origin と Fetch Metadata を確認する。CLI もローカル HTTP オリジン以外を受け付けない。既存コンテンツを消して初期化する運用は採らない。

ブラウザ検証は通常データと分離する。CMS の公開ライフサイクルと管理画面の操作に加え、ヘッダー・フッター・本文・記事・分類の各リンクをクリックし、直アクセスと再読込も確認する。HTTP 200 だけで成功とせず、見出しや本文、公開対象の有無を確認する。
