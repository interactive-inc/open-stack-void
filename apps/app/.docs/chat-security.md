# 信頼境界

パスワードの保管・再設定を非開発者に負担させないため、ログインはパスキーに限定する。招待は本人がパスキーを登録するための入口であり、メールリンクだけで継続的にログインできる仕組みにはしない。

最初の所有者にはサーバー環境変数の初期化キーを必要とする。キーを URL に入れると履歴やログに残るため、ブラウザで入力してパスキーを登録する。先着の匿名利用者が所有者になれる公開セットアップは採用しない。

サンプルは一つのチームを扱う。所有者の移譲や全パスキー紛失時の復旧は、別の本人確認設計が必要なため、自動のメールログインとして追加しない。予備のパスキーを登録できるようにする。

接続済みソケットは認証時点の権限を保持し続ける場合がある。そのため通知に本文を含めず、都度認可する取得処理で返す。

公開サイトの編集権限とは分離する。[[content-ownership]]。

MCP のログインはエージェントに秘密値を入力させず、本人がブラウザでパスキー確認して承認する。承認先と確認コードを照合し、プロセスが持つ検証用秘密と結び付ける。承認は5分で失効し、一度しか取得できない。拒否や取消後の再利用も認めない。
