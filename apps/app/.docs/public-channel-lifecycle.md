# Public channel continuity

The bounded goal is usable public-channel management and complete recovery after a disconnected reader misses several pages. This continues [[invitation-lifecycle]] and [[chat-security]]. Private membership, retention, automatic deletion, search, attachments and delivery outboxes remain outside this increment. The unanswered retention and uninvited-administrator private-access questions remain unresolved.

Inferred, reversible policy: active owners and administrators manage public channels; all active members may read them. Archive means pause new messages while retaining identity and history, with explicit restoration. It does not mean deletion or a retention deadline. Keeping the name reserved avoids accidentally creating a different room under an archived room's name. A renamed room retains its identity so links, loaded drafts and Durable Object history survive.

Authorization is checked at the server boundary and again at the Durable Object operation using the current session and membership. Archive and append share the room's serialization boundary: after an archive completes, a new append is rejected. A retry of a previously stored message remains successful after archive, provided its author and contents match and the session remains authorized. This avoids turning an uncertain successful delivery into a second message. Cross-database membership changes are not a distributed transaction; the current D1 authorization read is the operation's authorization point.

Socket invalidations disclose no message content. Check current access on subscription, heartbeat and before invalidation delivery; close stale sessions rather than automatically answering their heartbeats. Clients treat an explicit denial separately from an interrupted network request, preserving drafts during temporary failures.

Recover to a fixed sequence watermark in ascending pages, then repeat when notifications arrived during recovery. Merge by stable message identity and sequence, including older history loaded concurrently. Reject latest-page replacement: after a long disconnect it silently loses the middle. The watermark bounds each recovery pass even while writers are active. Reconnection is eventual while the browser can reach the server; this does not promise background delivery while a device is asleep.

Compatibility: the D1 migration only adds an archive flag with an active default; existing room resources, keys and SQL histories remain unchanged. Older code can still read the added column, but cannot enforce archive. Reverting code therefore cannot be called a safe operational rollback while any room is archived; restore rooms deliberately or retain enforcement. Never reset a database to roll back this change.

Evidence is provided by channel application tests, additive-migration compatibility, cache-recovery tests, and the isolated multi-actor Cloudflare journeys in `test/channels.spec.ts`. Actual execution results are reported separately; virtual authenticators do not prove real-device compatibility. [[verification]] and [[delivery]] govern completion and publication.

The existing authentication limiter uses calendar-minute buckets. Its burst regression must avoid straddling that boundary; otherwise two legitimate buckets make a 31-request assertion timing-dependent. This increment preserves the limiter policy. Clear previous account caches on successful login and discard in-flight recovery results after a cache reset, so delayed responses cannot restore a prior account's history.

The disconnect journey partitions only chat HTTP/WebSocket traffic and reconnects to the real isolated Durable Object. A browser-wide offline switch also disconnects Vite HMR and can reload the development page, invalidating the cache-continuity scenario. Keep the chat partition deterministic, hold a forward-history response while a live message is committed, then verify advancing watermarks and rendered order against persisted sequence. No synthetic history response replaces the server.
