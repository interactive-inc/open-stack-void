# 会話を続けられる操作

入力途中に部屋を移動して文章を失ったり、本人確認の未設定を端末の故障と誤解したりしないことを優先する。同じ画面内では部屋ごとに下書きを保持し、初回設定が未完了ならログイン操作へ誘導しない。端末の本人確認を取り消した場合も、利用者が次の操作を選べる案内を出す。[[chat-security]]。

誤字の修正と取り消しは投稿者本人が行う。他の端末で変更済みなら最新の内容を確認してもらい、古い画面の内容で上書きしない。削除は本文を消して投稿の位置だけを残す。送信時の識別子を保持し、古い送信を再試行しても削除した文章を復活させない。

検索は部屋に保存された履歴を対象とし、手元に読み込んだ投稿だけを検索する見せかけの操作にはしない。接続中と再接続中を文章で伝え、通知に本文を含めない方針を維持する。

最新版との統合では [[search-attachments]] と [[public-channel-lifecycle]] の検索・添付・再接続を正とし、旧い検索画面と定期取得処理を捨てた。編集・削除も部屋の実行境界で現在の認証情報を再確認し、アーカイブと添付の投稿を変更しない。添付の保存期間や削除は未決定なので、この変更で消さない。履歴は連番を保持して旧データへ列だけ追加し、既読範囲の古い投稿も再同期する。版番号を比較して遅れた応答で変更を巻き戻さない。読み込んだ履歴の再確認には履歴量に応じた通信が必要で、将来の変更カーソルは別の改善とする。

利用者からの「チャット機能とサイトのシードを作り込む」依頼、および最新版への統合依頼に基づく。本文変更は投稿者本人に限定する安全側の仮定で、管理者の代理削除や添付削除、非公開チャンネルは範囲外。Webと共有SDKの変更経路は同じサーバー規則を使い、CLI/MCPへの編集コマンド追加は行わない。本人・他人・失効セッション・競合・削除済みの再送・履歴の同期をローカルで確認する。実端末のパスキーと本番は別途確認が必要。
