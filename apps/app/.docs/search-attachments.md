# Public search and small attachments

Confirmed scope: make search and attachment upload/list/download useful for the current public channels and active members, through Web, CLI and MCP. Reuse [[public-channel-lifecycle]] authorization. Private administrator access and retention remain unanswered. No outbox, account expansion, destructive cleanup, new credentials, external buckets or production operation belongs to this increment.

Inferred sample limits are deliberately reversible: a file may be at most 512KiB; each room may retain at most 200 files and 16MiB of file bytes. Existing messages, filenames and metadata consume additional SQLite storage, so the byte count is a payload budget, not a billing estimate. The count also bounds per-room metadata growth. Only managers can create additional public rooms under the existing policy. There is no claimed whole-workspace spending budget or production-scale attachment service; that budget requires explicit operational design. Never automatically delete old files to free capacity while retention is unresolved.

The existing room Durable Object is a provisional small-file storage adapter. It avoids creating an R2 resource without authorization and lets the file and its message commit in one SQLite transaction. Preserve the room resource name and instance identities; initialize only an additional table. Store no user-supplied path or URL. A stable random attachment identity is scoped to the server-selected room. Retry compares author, canonical filename/type and content digest before returning the existing result, including after archive. A different submission under the same identity is rejected. Failed inserts roll back both message and file, and quota is checked inside the room's existing serialization boundary. Archive pauses new writes while keeping authorized reads.

Reject turning this choice into a core convention or an answer for large media. The repository boundary must continue to hide byte storage from clients. A later R2 adapter should preserve public attachment/message IDs and authenticated API URLs, derive internal keys from an explicit workspace/room/attachment namespace, stream to a private staging object, verify length/digest, and commit the pointer through the room authority. A reviewed reconciliation and migration protocol is necessary for staging failures and existing blobs; do not pretend an external object write participates in SQLite's transaction. Migration needs approved resources, copy-and-verify evidence and a compatibility/rollback plan before changing reads or deleting anything. No such migration is performed here.

Allow only PNG/JPEG/WebP signatures and strict UTF-8 text. Signature checks are not full image decoding, malware scanning or proof that a file is benign. Canonical extensions and forced octet-stream downloads with nosniff, sandbox CSP, same-origin resource policy and no-store are independent defenses. The UI renders only escaped filename metadata; neither image nor HTML/PDF active content is opened inline. Text that looks like HTML remains data. Limit multipart bytes before parsing, file bytes before copying/decoding, Node multipart serialization and response buffering, SDK download streams and CLI file reads. MCP accepts bounded canonical base64 file data, never filesystem paths or authentication secrets; browser approval remains the authentication mechanism.

Search is literal text matching within the selected room, including filenames represented by attachment messages; it does not index file bodies. Return at most 50 escaped plain-text snippets per page and examine a window of at most 5,000 messages. Preserve an initial sequence watermark while paging. Expose a continuation and completion state; an empty partial window must not say the entire history has no matches. Fetch the full selected message through current authorization. Search terms travel in a POST body rather than a loggable query URL. Do not mint public or signed attachment URLs or expose storage paths/digests in metadata.

Check the current session and active membership in the room operation for every search, full-message read, upload, list and download. Reuse existing invalidation-only realtime events and reject stale sessions instead of granting access from cached metadata. The current sample is one workspace per repository, not a multi-tenant service: reject invented workspace selectors and cross-room object substitution, and test synthetic foreign credentials. Do not claim two deployed workspaces were exercised or introduce tenant policy implicitly.

Evidence includes domain limits and signature tests, bounded CLI reads, shared transport journeys and isolated Cloudflare multi-user tests. Synthetic fixtures populate a 5,001-message history and inject a failing SQLite trigger only into a positively identified isolated room to verify continuation and transaction rollback. The test helper refuses normal state. Concurrent attempts at count/byte budgets, invalid formats and paths, active-looking content, expired/disabled/outsider actors, archive races, stale sockets and uncertain upload responses are acceptance cases. Actual execution results are reported separately under [[verification]] and [[delivery]]. Real-device passkeys, real mail, a second deployed workspace, malware scanning, production spending controls and R2 migration remain unverified or outside scope.

The installed body-limit middleware returned early without cancelling unread input; an oversized declared upload became a development-proxy 500 instead of 413. Keep the same byte caps and explicitly cancel rejected declared or chunked input, retaining only bounded chunks for accepted bodies. Unit and real local runtime checks cover both framing modes and verify that rejected data never reaches a handler or storage.

CLI and MCP upload entry points require a public request ID so an uncertain response can be retried without a second file. The browser retains its generated ID with the selected file. MCP checks encoded length before evaluating canonical base64 or decoding bytes. Repeating an intended new upload with a new ID is a new operation, not content-based global deduplication.

Bounded cancellation alone does not fix the upstream service-binding reset: the actual Playwright multipart client still lost a 2MiB rejection. See [workers-sdk #15819](https://github.com/cloudflare/workers-sdk/issues/15819) and [#15027](https://github.com/cloudflare/workers-sdk/issues/15027). Use the supported Vite dev/preview middleware boundary to reject declared oversized input before forwarding and count chunked bytes without buffering or starting their flow. The initial attempt closed rejected HTTP connections after the JSON 413; keep Worker limits and authorization as the independent application boundary. The budget function is shared, and accepted payload bytes must arrive unchanged. Local probes cover 600KiB/2MiB/8MiB and chunked 8MiB, without an unbounded drain, vendor patch or raised cap. This is a local ingress mitigation, not a claim that the upstream runtime defect or a production service-binding path has been fixed; deployment-path behavior remains unverified.

Hosted CI 40413250132 disproved the initial local success guarantee: closing the socket before a 2MiB sender had finished produced ECONNRESET. Retain the same acceptance limits, send the JSON rejection with keep-alive, and discard only rejected input up to 4MiB total and for at most two seconds, without storing or decoding it. Complete the HTTP request when it fits this fixed rejection budget; otherwise pause reading and terminate the socket at the deadline. Arbitrarily large/slow hostile inputs may therefore be disconnected instead of receiving a complete JSON error. This is an explicitly bounded transport cost, not a larger accepted upload limit. Tests delay response reads and verify both byte and time termination; the original 2MiB/413 assertion remains unchanged.
