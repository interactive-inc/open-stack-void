# 日々の連絡に使う最小構成

ユーザーの「必要最低限だけど業務で使えるツールにする」を今回の到達点とする。連絡を見落とさず、どの相談への返事か分かり、通信が途切れても文章を失わず再送できることを優先する。理想の汎用チャットという未限定の目標を、この利用場面へ絞る。[[chat-usability]]、[[public-channel-lifecycle]]。

閲覧範囲は、ユーザーが「全員共有で始める」と回答したため、招待メンバー全員共有で確定した。部署・案件を限定する運用は今回の対象にしない。DM、非公開チャンネル、スレッドの枝分かれ、外部プッシュ、メール通知、添付の保存期間と削除は未決定または範囲外とする。秘密の案件に使えるとは説明しない。

未読は本人の確認位置であり、他の参加者に読了を知らせない。自分の投稿と削除済み本文は未読件数に数えず、表示は99件超でまとめる。会話の末尾を前面で表示した場合のみ確認を進め、背景タブ・管理画面・過去の履歴閲覧では進めない。保存時は現在の認証と所属を部屋で確認し、未来の連番まで進めず、遅れた更新で巻き戻さない。CLIとMCPは明示した確認操作だけが状態を変える。部屋ごとに本人だけの位置を追加保存し、既存の投稿と資源識別子を維持する。これは配信保証や他者の既読証明ではない。

返信は同じ部屋の投稿への参照として保存し、引用本文を複製しない。返信元の取得にも現在の認可を適用し、編集と削除を表示へ反映する。別の部屋・未存在・削除済みの投稿への新規返信は拒否する。添付投稿への返信は許可するが添付の変更規則は変えない。新しい返信先は送信内容の変更なので識別子も変え、同じ識別子の異なる返信先は競合とする。

下書きと送信識別子、返信先は同じ画面の部屋ごとに保持する。失敗した送信は同じ識別子で再送し、遅れた成功で新しい下書きを消さない。共有端末に本文を残さないため、永続的なブラウザ保存は追加しない。画面を閉じた後の復元と未確定送信の端末間移送は保証しない。[[search-attachments]] の小容量制限と招待・パスキー管理を維持する。

紹介サイトは実際の業務利用と導入手順を主とし、開発基盤の説明を副とする。既存の「開発用ひな形だけを紹介する」方針を今回の目的に合わせて変更する。未実装の機能や本番の配信完了を宣伝しない。記事管理者の編集内容と公開状態は維持し、公開データをこのローカル作業で書き換えない。[[user-guide]]。

検証では二人の独立した確認位置、順不同の確認、背景表示、返信先の認可と削除、応答途絶後の再送と部屋切り替えを扱う。Web・SDK・CLI・MCPは同じ規則を使用し、実行した結果は [[local-verification]] に記録する。実端末・実メール・本番導入は別の検証であり、ローカル成功から業務運用済みと結論しない。残る運用作業は利用者本人のパスキー登録、実メールの配信設定、閲覧範囲の確認、既存公開内容の確認と本番反映である。

仮想ブラウザでは各タブへのフォーカス強制があるため、背景閲覧の試験ではその強制を解除し、実際にフォーカスを失ったことを前提として確認する。検索と添付の非実行性を確かめる既存試験では、厳密なアプリ名に正規の未読件数だけを許容し、投稿内容によるタイトル書き換えは引き続き失敗とする。

今回のローカル実装では、全員共有の範囲に未読・返信・安全な再送を追加した。残る製品機能を際限なく増やさず、実メールと実端末での受け入れ、本番の内容更新を運用開始条件として残す。紹介画面からは利用案内だけでなく記事一覧へも戻れる経路を維持する。
